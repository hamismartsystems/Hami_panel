## چرا پنل حامی؟

پنل‌های امروز خوب‌اند، اما یک نقطهٔ کور مشترک دارند: **وقتی لینک خراب تولید می‌کنند،
خودشان نمی‌فهمند.** لینک سالم به نظر می‌رسد، ذخیره می‌شود، به مشتری تحویل داده می‌شود —
و فقط وقتی مشتری زنگ می‌زند می‌فهمیم که ترافیک نمی‌آید.

نمونه‌های مستند از پنل‌های موجود:

| مشکل | منبع |
|---|---|
| تنظیمات Reality از یک اینباندِ دیگر به اینباند XHTTP نشت می‌کند ⇒ لینکی که «درست» است ولی کار نمی‌کند | [3x-ui #4987](https://github.com/MHSanaei/3x-ui/issues/4987) · [بازگشتِ دوباره #6424](https://github.com/MHSanaei/3x-ui/issues/6424) |
| به‌روزرسانیِ هسته بی‌سروصدا Reality را شکست؛ پنل می‌گفت «هسته سالم است» | [3x-ui #5922](https://github.com/MHSanaei/3x-ui/issues/5922) |
| تک‌نقطهٔ شکست؛ چندسروره یعنی نصبِ چند پنلِ جداگانه | [مقایسه](https://valebyte.com/en/blog/marzban-vs-3x-ui-choosing-your-vpn-panel/) |
| 3x-ui رسماً می‌گوید برای استفادهٔ شخصی است، نه تولید | [مقایسه](https://smartvds.org/hosting-basics/marzban-vs-3x-ui/) |
| محدودیتِ تعداد دستگاه، هشدارِ اتمام حجم و محدودیتِ سرعت ندارد | [منبع](https://valebyte.com/en/blog/3x-ui-marzban-how-to-set-user-traffic-limits/) |
| کاربران سال‌ها درخواستِ چندسروره کرده‌اند و بی‌جواب مانده | [3x-ui #3031](https://github.com/MHSanaei/3x-ui/issues/3031) |

### شش ستونِ پنل حامی

1. **هر کانفیگ قبل از تحویل واقعاً تست می‌شود.** پنل با همان لینک وصل می‌شود و تأیید
   می‌کند که ترافیک رد شده؛ «ذخیره شد» کافی نیست.
2. **تولیدِ لینک قطعی و تست‌پذیر است.** لینک فقط از اینباندی ساخته می‌شود که کاربر
   واقعاً به آن وصل است؛ هیچ جستجوی سراسری و ادغامِ پنهانی وجود ندارد
   (ببینید: `internal/link/link_test.go`).
3. **نسخهٔ هسته پین می‌شود** و ارتقا مرحله‌به‌مرحله با آزمونِ «کانِری» و بازگشت خودکار انجام می‌گیرد.
4. **سلامت در خودِ پنل است:** پورت، TLS، صحتِ لینکِ واقعی، اتمادِ حجم — با هشدار و
   تعمیرِ خودکارِ موارد شناخته‌شده.
5. **چندسروره از روز اول:** هر گره یک عاملِ سبک؛ ساب‌لینکِ هوشمند فقط گره‌های سالم را برمی‌گرداند.
6. **مهاجرت‌پذیری:** وارداتِ مستقیم از 3x-ui و مرزبان، بدون ساختنِ دوبارهٔ کاربران.

## معماری

```
                    ┌───────────────────────────────┐
   مرورگر مدیر  ───▶│  Hami Panel  (Go, تک‌فایل نصب) │
   ربات تلگرام  ───▶│  API · وب‌سرویس · زمان‌بند      │
   مشتری (ساب)  ───▶│  تولید لینک · تستِ کانفیگ      │
                    └───────────┬───────────────────┘
                                │  گره‌ها (همین سرور یا سرور دیگر)
                    ┌───────────▼───────────────────┐
                    │  عاملِ حامی (Go, سبک)          │
                    │  Xray / sing-box · ترافیک     │
                    └───────────────────────────────┘
```

| بخش | انتخاب | دلیل |
|---|---|---|
| زبان | Go | تک‌فایل نصب، کم‌مصرف، مناسبِ شبکه، نزدیک به اکوسیستمِ Xray |
| پایگاه داده | SQLite (پیش‌فرض) / PostgreSQL | نصبِ ساده در مقیاسِ کوچک، رشد بدون دردسر |
| هسته | Xray (پیش‌فرض) + sing-box (Hysteria2 / TUIC / AnyTLS) | پوششِ کاملِ پروتکل‌ها |
| رابط | React + API-first | هم رابطِ مدرن، هم قابلِ اسکریپت‌نویسی |
| نصب | اسکریپتِ یک‌خطی + پشتیبان‌گیری/بازیابی یک‌دستوری | تجربهٔ اولیه بی‌دردسر |

## وضعیت پروژه

| بخش | وضعیت |
|---|---|
| تولید و اعتبارسنجیِ لینک (vless / vmess / trojan / ss) + تست | ✅ انجام‌شده |
| ساب‌لینک (base64) | ✅ انجام‌شده |
| پایگاه داده و مدلِ کاربر/اینباند/ترافیک/گره/رویداد | ✅ انجام‌شده (`internal/store`) |
| مدیریتِ فرایندِ Xray و تولیدِ کانفیگ سازگار با لینک | ✅ `hami gen` + `internal/xray` |
| **تستِ واقعیِ کانفیگ (canary)** | ✅ `hami canary` — عبورِ ترافیک با خودِ لینک |
| رابطِ وب، API عمومی، بات تلگرام، چندسروره، مهاجرت | 📋 برنامه‌ریزی‌شده |

## اجرا و تست (مشارکت‌کنندگان)

```bash
git clone https://github.com/hamismartsystems/Hami_panel
cd hami-panel
go test ./...          # لینک، پایگاه، کانفیگِ Xray — باید همه سبز باشد
# آزمونِ زنده؛ بدون XRAY_BIN این بخش رد می‌شود، نه اینکه سبزِ دروغین بدهد
XRAY_BIN=/path/to/xray go test ./internal/xray/ -count=1 -run Canary
go build -o hami ./cmd/hami
./hami gen -spec inbounds.json -out config.json
./hami canary -spec inbounds.json -xray /path/to/xray
```

`inbounds.json` همان اینباندی است که لینک از آن ساخته می‌شود، به‌اضافهٔ `privateKey`
و `dest` که فقط در کانفیگِ سرور می‌آیند. اگر Reality نیمه‌کاره باشد، دستور خطا
می‌دهد و فایل را به‌عنوانِ کانفیگِ سالم تحویل نمی‌دهد. `hami canary` کلاینت را
فقط از لینکِ ساخته‌شده می‌سازد، نه از کلیدِ خصوصیِ سرور.
