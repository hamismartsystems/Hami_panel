## مدلِ توزیع

پنل حامی برای **نصبِ مستقل روی سرورِ هر اپراتور** آماده می‌شود؛ این مخزن یک سرویس SaaS یا پنلِ مشترکِ میزبانی‌شده ارائه نمی‌کند. هر اپراتور پایگاه داده و هستهٔ خودش را روی سرور خودش اجرا می‌کند.

## چرا پنل حامی؟

پنل‌های امروز خوب‌اند، اما یک نقطهٔ کور مشترک دارند: **وقتی لینک خراب تولید می‌کنند،
خودشان نمی‌فهمند.** لینک سالم به نظر می‌رسد، ذخیره می‌شود، به مشتری تحویل داده می‌شود —
و فقط وقتی مشتری زنگ می‌زند می‌فهمیم که ترافیک نمی‌آید.

نمونه‌های مستند از پنل‌های موجود:

| مشکل | منبع |
|---|---|
| تنظیمات Reality از یک اینباندِ دیگر به اینباند XHTTP نشت می‌کند ⇒ لینکی که «درست» است ولی کار نمی‌کند | [3x-ui #4987](https://github.com/MHSanaei/3x-ui/issues/4987) · [بازگشتِ دوباره #6424](https://github.com/MHSanaei/3x-ui/issues/6424) |
| به‌روزرسانیِ هسته بی‌سروصدا Reality را شکست؛ پنل می‌گفت «هسته سالم است» | [3x-ui #5922](https://github.com/MHSanaei/3x-ui/issues/5922) |
| تک‌نقطهٔ شکست؛ چندسروره یعنی نصبِ چند پنلِ جداگانه | [مقایسه](https://valebyte.com/en/blog/marzban-vs-3x-ui-choosing-your-vpn-panel/) |
| 3x-ui رسماً می‌گوید برای استفادهٔ شخصی است، نه تولید | [مقایسه](https://smartvds.org/hosting-basics/marzban-vs-3x-ui/) |
| محدودیتِ تعداد دستگاه، هشدارِ اتمام حجم و محدودیتِ سرعت ندارد | [منبع](https://valebyte.com/en/blog/3x-ui-marzban-how-to-set-user-traffic-limits/) |
| کاربران سال‌ها درخواستِ چندسروره کرده‌اند و بی‌جواب مانده | [3x-ui #3031](https://github.com/MHSanaei/3x-ui/issues/3031) |

### شش ستونِ پنل حامی

1. **هر کانفیگ قبل از تحویل واقعاً تست می‌شود.** پنل با همان لینک وصل می‌شود و تأیید
   می‌کند که ترافیک رد شده؛ «ذخیره شد» کافی نیست.
2. **تولیدِ لینک قطعی و تست‌پذیر است.** لینک فقط از اینباندی ساخته می‌شود که کاربر
   واقعاً به آن وصل است؛ هیچ جستجوی سراسری و ادغامِ پنهانی وجود ندارد
   (ببینید: `internal/link/link_test.go`).
3. **نسخهٔ هسته پین می‌شود** و ارتقا مرحله‌به‌مرحله با آزمونِ «کانِری» و بازگشت خودکار انجام می‌گیرد.
4. **سلامت در خودِ پنل است:** پورت، TLS، صحتِ لینکِ واقعی، اتمادِ حجم — با هشدار و
   تعمیرِ خودکارِ موارد شناخته‌شده.
5. **چندسروره از روز اول:** هر گره یک عاملِ سبک؛ ساب‌لینکِ هوشمند فقط گره‌های سالم را برمی‌گرداند.
6. **مهاجرت‌پذیری:** وارداتِ مستقیم از 3x-ui و مرزبان، بدون ساختنِ دوبارهٔ کاربران.

## معماری

```
                    ┌───────────────────────────────┐
   مرورگر مدیر  ───▶│  Hami Panel  (Go, تک‌فایل نصب) │
   ربات تلگرام  ───▶│  API · وب‌سرویس · زمان‌بند      │
   مشتری (ساب)  ───▶│  تولید لینک · تستِ کانفیگ      │
                    └───────────┬───────────────────┘
                                │  گره‌ها (همین سرور یا سرور دیگر)
                    ┌───────────▼───────────────────┐
                    │  عاملِ حامی (Go, سبک)          │
                    │  Xray / sing-box · ترافیک     │
                    └───────────────────────────────┘
```

| بخش | انتخاب | دلیل |
|---|---|---|
| زبان | Go | تک‌فایل نصب، کم‌مصرف، مناسبِ شبکه، نزدیک به اکوسیستمِ Xray |
| پایگاه داده | SQLite | فایلِ محلی، بی‌نیاز از سرویسِ جداگانهٔ پایگاه داده |
| هسته | Xray (پیش‌فرض) + sing-box (Hysteria2 / TUIC / AnyTLS) | پوششِ پروتکل‌های پیاده‌سازی‌شده |
| رابط | HP-UI با HTML/CSS/JavaScript توکار + API | بدون نیاز به CDN یا asset بیرونی |
| نصب | اسکریپتِ محلیِ systemd + پشتیبان‌گیری/بازیابی یک‌دستوری | نصبِ مستقل روی سرور اپراتور |

## نصب و استفادهٔ self-hosted

نصابِ این مخزن برای Linux دارای `systemd` است و روی معماری‌های `amd64` و `arm64`، هستهٔ Xray نسخهٔ پین‌شدهٔ `26.3.27` را نصب می‌کند. دریافت Xray از انتشار رسمی GitHub با SHA-256 ثابت بررسی می‌شود. نصب‌کننده خودش پورت فایروال را باز نمی‌کند.

### پیش‌نیازها

- دسترسی `root` یا `sudo` و `systemd` فعال.
- `curl`، `sha256sum` و `python3` روی سرور.
- Go نسخهٔ `1.27` یا جدیدتر برای ساخت باینری Hami. باینری را روی سرور مقصد بسازید یا برای همان معماری Linux بسازید.
- ارتباط خروجی با GitHub برای دریافت آرشیو Xray.

### ساخت و نصب

```bash
git clone https://github.com/hamismartsystems/Hami_panel.git
cd Hami_panel
go build -trimpath -o hami ./cmd/hami
sudo env HAMI_BIN="$PWD/hami" bash ./scripts/install.sh
```

مقادیر پیش‌فرض نصب:

| مورد | مقدار |
|---|---|
| پنل | `127.0.0.1:8080` فقط روی loopback |
| باینری Hami | `/opt/hami/hami` |
| پایگاه داده | `/var/lib/hami/panel.db` |
| پیکربندی Xray | `/etc/hami/xray.json` |
| سرویس‌ها | `hami-panel.service` و `hami-xray.service`؛ با بوت فعال می‌شوند |

اگر پورت پیش‌فرض روی سرور آزاد نیست، یک پورت آزادِ loopback انتخاب کنید؛ مثلاً:

```bash
sudo env HAMI_BIN="$PWD/hami" HAMI_LISTEN_ADDR=127.0.0.1:18080 bash ./scripts/install.sh
```

برای ساخت لینک اشتراک با نشانی عمومیِ ثابت، هنگام نصب `HAMI_BASE_URL` را هم تنظیم کنید؛ در این مثال HTTPS و نام دامنه را با مقدار خودتان جایگزین کنید:

```bash
sudo env HAMI_BIN="$PWD/hami" HAMI_BASE_URL=https://panel.example.com bash ./scripts/install.sh
```

`HAMI_ENABLE_AT_BOOT=no` سرویس‌ها را همین حالا اجرا می‌کند، اما برای شروع خودکار در بوت فعالشان نمی‌کند. نصاب روی unitهای موجود یا دایرکتوری‌های مقصدِ غیرخالی overwrite نمی‌کند؛ اگر اجرا نیمه‌کاره ماند، اول وضعیت سرویس و فایل‌های ایجادشده را بررسی کنید و نصاب را کورکورانه دوباره اجرا نکنید.

### ورود و کار روزمره

پس از نصب، برای ساخت نخستین مدیر این دستور را اجرا کنید؛ گذرواژهٔ قوی فقط همان یک‌بار چاپ می‌شود، آن را در جای امن نگه دارید و در خط فرمان به‌صورت `-password` ننویسید:

```bash
sudo /opt/hami/hami admin create -db /var/lib/hami/panel.db -user admin
```

پنل عمداً فقط روی loopback گوش می‌دهد. برای ورود از رایانهٔ خود، تونل SSH بسازید:

```bash
ssh -N -L 8080:127.0.0.1:8080 <user>@<server>
```

سپس در مرورگر همان رایانه `http://127.0.0.1:8080/hp-ui/login` را باز کنید. اگر هنگام نصب پورت دیگری انتخاب کرده‌اید، همان پورت را در دو جای دستور تونل و نشانی مرورگر بگذارید. برای دسترسی از راه اینترنت، backend را روی loopback نگه دارید و فقط از reverse proxy با HTTPS عبور دهید؛ خودِ نصب‌کننده reverse proxy یا گواهی TLS نمی‌سازد. در آن حالت `HAMI_BASE_URL` را روی URL عمومی HTTPS تنظیم کنید و مسیر `/sub/` را نیز از proxy عبور دهید.

برای ساخت کانفیگ از داشبورد:

1. در بخش **Inbounds**، گزینهٔ **New inbound** را بزنید، قالب را انتخاب کنید و نشانی عمومی و یک پورت آزاد را وارد کنید. در قالب‌های Reality کلیدها خودکار ساخته می‌شوند.
2. پورت انتخاب‌شده باید روی سرور قابل استفاده باشد؛ پورت ترافیک را جداگانه در فایروال/سیاست شبکهٔ خودتان باز کنید. نصاب فایروال را تغییر نمی‌دهد.
3. پنل کانفیگ Xray را می‌سازد و سرویس Xray را به‌روز می‌کند. سپس در **Users** کاربر تازه بسازید، اینباند را انتخاب کنید و سهمیه/مدت/محدودیت دستگاه را تنظیم کنید.
4. لینک اشتراک را از داشبورد به کاربر بدهید. توکنِ لینک مثل گذرواژه است؛ آن را عمومی نکنید. لینک اشتراک با تغییرات اینباند به‌روزرسانی می‌شود.

برای وضعیت سرویس و گزارش خطا:

```bash
sudo systemctl status hami-panel.service hami-xray.service
sudo journalctl -u hami-panel.service -u hami-xray.service -n 100 --no-pager
```

**محدودهٔ این نصاب:** فقط Xray را نصب و به سرویس محلی وصل می‌کند. قالب‌های sing-box (مانند Hysteria2، TUIC و AnyTLS) در فهرست قالب‌ها هستند، اما نصب و مدیریت sing-box با این اسکریپت انجام نمی‌شود و باید جداگانه پیکربندی شود.

## اجرا و تست (مشارکت‌کنندگان)

```bash
git clone https://github.com/hamismartsystems/Hami_panel
cd hami-panel
go test ./...          # لینک، پایگاه، کانفیگِ Xray — باید همه سبز باشد
# آزمونِ زنده؛ بدون XRAY_BIN این بخش رد می‌شود، نه اینکه سبزِ دروغین بدهد
XRAY_BIN=/path/to/xray go test ./internal/xray/ -count=1 -run Canary
go build -o hami ./cmd/hami
./hami gen -spec inbounds.json -out config.json
./hami canary -spec inbounds.json -xray /path/to/xray
./hami guard -spec inbounds.json
```

`inbounds.json` همان اینباندی است که لینک از آن ساخته می‌شود، به‌اضافهٔ `privateKey`
و `dest` که فقط در کانفیگِ سرور می‌آیند. اگر Reality نیمه‌کاره باشد، دستور خطا
می‌دهد و فایل را به‌عنوانِ کانفیگِ سالم تحویل نمی‌دهد. `hami canary` کلاینت را
فقط از لینکِ ساخته‌شده می‌سازد، نه از کلیدِ خصوصیِ سرور.
