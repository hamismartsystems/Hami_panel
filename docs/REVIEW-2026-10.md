## ۳. نقاط قوت (با ارجاع به کد)

1. **تضمینِ «لینک با اینباندِ خودش» واقعاً تست دارد، نه فقط ادعا.**
   `TestRealityConfigMatchesLinkAndDoesNotLeak` و `TestXHTTPDoesNotInheritReality` (`internal/xray/config_test.go:25,112`) همان شکافی را می‌پوشانند که پنل‌های دیگر شکست خوردند.

2. **مهاجرت ایمن است.** منبع فقط‌خواندنی باکس کپی می‌شود، چک‌سام قبل/بعد مقایسه می‌شود، `plan` چیزی نمی‌نویسد، `apply` بی‌`-yes` اجرا نمی‌شود و اجرای دوباره چیزی را تکرار نمی‌کند (`internal/importer/*`، تست‌های `TestSourceIsNeverModified`، `TestApplyThenRerunImportsNothingTwice`).

3. **اعمالِ تغییرات در هسته سنجیده است:** debounce، نوشتن اتمیک (`.new` + `rename`)، و **خودداری از نوشتنِ کانفیگِ خالی** که همه را آفلاین می‌کند (`internal/apply/apply.go:78‑110`).

4. **نگهبانِ هوشمند:** پورت بسته → فقط یک ری‌استارت با همان مشخصات؛ کلید/SNI اشتباه → فقط هشدار، بدون کپیِ تنظیماتِ اینباند دیگر (`internal/guard/guard.go`، تست‌ها همه سبز).

5. **احراز هویت درست پیاده شده:** PBKDF2-SHA256 با ۲۱۰٬۰۰۰ دور و نمکِ تازه، مقایسهٔ زمان‌ثابت، کوکی `HttpOnly` و `Secure` پشت TLS، ابطالِ نشست با تغییرِ گذرواژه (`internal/store/admins.go`).

6. **سطحِ حملهٔ عاملِ گره حداقلی است:** فقط `GET /health` با امضای HMAC کلِ بدنه + پنجرهٔ ۶۰ ثانیه + مقایسهٔ زمان‌ثابت (`internal/agent/`).

7. **نصاب سخت‌گیر است:** checksum ثابتِ Xray، اجبار به loopback، امتناع از بازنویسی، و sandbox‌کردنِ سرویس‌ها (`UMask=0077`, `ProtectSystem=strict`, `ProtectHome`) — `scripts/install.sh`.

8. **بدونِ سطحِ تزریق:** هیچ کوئریِ ساخنه‌شده با `Sprintf`، هیچ `sh -c`، هیچ `exec` با ورودیِ کاربر (به‌جز آرگومان‌های کنترل‌شدهٔ `systemctl`)، و در رابط وب همه‌جا `esc()` استفاده شده (۴۱ بار) — `innerHTML` با دادهٔ خام نداریم.

9. **دیسیپلین مخزن:** صفر `TODO/FIXME`، صفر کدِ مُرده، مستندات فارسیِ دقیق، و روادمپِ صادقانه (مواردِ انجام‌نشده واضح علامت خورده‌اند).

## ۴. یافته‌ها به‌تفصیل

### 🔴 F1 — نصاب، جمع‌آوریِ ترافیک را زمان‌بندی نمی‌کند
**کجاست:** `scripts/install.sh:55‑56,166‑168` فقط `hami-panel.service` و `hami-xray.service` را می‌سازد. هیچ `timer`/`cron`ی برای `hami traffic collect` یا `hami notice` نصب نمی‌شود.

**چرا مهم است:** `internal/traffic/traffic.go` تنها جایی است که سهمیه را واقعاً «تمام» می‌کند (`Apply` → `SetClientEnabled(false)`). بدون اجرای دقیقه‌ای:
- سهمیهٔ کاربر هرگز تمام نمی‌شود، مصرف در داشبورد صفر می‌ماند، «آنلاین» هیچ‌وقت روشن نمی‌شود؛
- ولی README (خط ۹۲) و ROADMAP (خط ۸۳) صریح می‌گویند «جمع‌آوری هر دقیقه، سهمیه که واقعاً تمام می‌شود» — یعنی **رفتارِ محصول با آنچه مستند شده یکی نیست**.

**پیشنهاد:** در نصاب دو یونیت اضافه شود:
```ini
# hami-traffic.timer → OnBootSec=60s، OnUnitActiveSec=60s
ExecStart=/opt/hami/hami traffic collect -db /var/lib/hami/panel.db \
          -xray /var/lib/hami/xray/xray -quiet
# hami-notice.timer → OnCalendar=hourly
ExecStart=/opt/hami/hami notice -db /var/lib/hami/panel.db -days 3 -ratio 0.8
```
(یا جایگزین: یک زمان‌بندِ داخلی در `hami web serve`، مشروط بر پرچم `-schedule`.)

### 🔴 F2 — انقضا در هسته اعمال نمی‌شود؛ لینکِ ذخیره‌شده پس از انقضا کار می‌کند
**کجاست:** `internal/xray/fromstore.go:29` فقط `if !c.Enable { continue }` را بررسی می‌کند؛ `ExpireAt` و سهمیه در هیچ‌کدام از مسیرهای ساختِ کانفیگ لحاظ نمی‌شوند. تنها مصرف‌کنندهٔ انقضا، فیلترِ ساب‌لینک است (`internal/subs/subs.go` → `ActiveNow`).

**آزمون عملی که انجام دادم:**
```
hami user set -db smoke.db -email ali@test -expire-at 2026-10-01T03:32:59Z   # گذشته
hami gen -db smoke.db -out out2.json
  → inbound in-1 clients: ['ali@test']      ← کاربرِ منقضی هنوز در کانفیگِ هسته است
curl /sub/<token>  → "[]"                    ← ساب‌لینک درست خالی است
```
**اثر:** مشتری‌ای که کانفیگ را ذخیره کرده (یا اپش کش کرده) **پس از پایانِ اشتراک به کار ادامه می‌دهد**، چون UUID همچنان در کانفیگِ زندهٔ Xray هست و ترافیکش رد می‌شود. این دقیقاً همان چیزی است که «سهمیه/انقضایی که نمایشی است نه واقعی» خوانده می‌شود.

**پیشنهاد (کم‌هزینه و هم‌راستا با فلسفهٔ پروژه):** در `EndpointsFromStore` قبل از افزودن کلاینت:
```go
if c.ExpireAt != nil && !time.Now().Before(c.ExpireAt.UTC()) { continue }
if c.TotalBytes > 0 && c.UpBytes+c.DownBytes >= c.TotalBytes { continue }
```
به‌همراه یک `AddEvent` توضیحی و بازسازیِ کانفیگ در اجرای `traffic collect` (تا کاربری که همین لحظه سهمیه‌اش تمام شد، بی‌درنگ خاموش شود). تستِ پیشنهادی: «کلاینتِ منقضی در کانفیگ نیست ولی ردیفش در پایگاه‌داده می‌ماند».

### 🟠 F3 — دور زدنِ سدِ ورود با هدر جعلیِ `X-Forwarded-For`
**کجاست:** `internal/web/auth.go:103`
```go
func clientKey(r *http.Request) string {
    if xf := r.Header.Get("X-Forwarded-For"); xf != "" { … return xf }
    …
}
```
کلیدِ محدودکنندهٔ تلاشِ ناموفق از هدرِ کنترل‌شده توسطِ کلاینت گرفته می‌شود. مهاجم با ارسال `X-Forwarded-For` تازه در هر درخواست، هر بار «سطل» نو می‌گیرد و می‌تواند بدون سد، گذرواژه‌ها را امتحان کند. همچنین `ip=` ثبت‌شده در لاگِ رویدادها و هشدارهای ورود قابلِ جعلِ کامل است (بی‌اعتبار شدنِ ردگیری).

**پیشنهاد:** یکی از این دو:
- پیش‌فرض `RemoteAddr`؛ خواندن `X-Forwarded-For` **فقط** وقتی `RemoteAddr` در فهرست پروکسی‌های مطمئن باشد و آدرس، **آخرین** مقدار درست را از راست بدهد — با پرچمِ `-trusted-proxies 127.0.0.1/8`;
- یا الگوی رایج: `X-Real-IP` تنها از پروکسیِ داخلی.

### 🟡 F4 — احتمال از‌دست‌رفتنِ ویرایشِ مدیر در پنجرهٔ جمع‌آوری
**کجاست:** `internal/traffic/traffic.go:145‑190` همهٔ کاربران را می‌خواند، روی نمونهٔ حافظه‌ای جمع می‌زند و بعد `st.UpdateClient(&c)` را صدا می‌زند؛ ولی `UpdateClient` (`internal/store/users.go:70`) **کلِ ردیف** را می‌نویسد (quota، expire، ip_limit، flow، …).

**اثر:** اگر مدیر همان لحظه از داشبورد سهمیه/انقضای کاربری را عوض کند (فرایندِ دیگری)، نوشتنِ جمع‌کننده با دادهٔ کهنه، تغییرِ مدیر را بی‌صدا برمی‌گرداند. با ۱٬۰۰۰ کاربر این پنجره چند ثانیه است، نه میلی‌ثانیه.

**پیشنهاد:** جایگزینی با به‌روزرسانیِ هدفمند و اتمیک در یک تراکنش:
```sql
UPDATE clients SET up_bytes = up_bytes + ?, down_bytes = down_bytes + ?,
  last_seen = ? WHERE id = ?
```
و سپس خواندنِ تازه برای تصمیمِ سهمیه. (در `store.go` تابعِ آمادهٔ `AddTraffic` هم موجود است که همین را در تراکنش انجام می‌دهد و جدول `traffic` را هم پر می‌کند — یعنی جمع‌کننده بهتر است از آن استفاده کند و تاریخچهٔ مصرف هم بنویسد.)

### 🟡 F5 — امضای عاملِ گره، query string را پوشش نمی‌دهد
**کجاست:** `internal/agent/auth.go` — امضا روی `ts\nMETHOD\nPATH\nSHA256(body)` است. اگر در آیندهٔ نزدیک پارامتری به query اضافه شود (مثلاً `?limit=`، `?node=`)، یک واسطهٔ شبکه می‌تواند آن را تغییر دهد بدون آنکه امضا بشکند. (سطح حملهٔ فعلی فقط `GET /health` است، پس امروز آسیبِ عملی ندارد؛ ولی «کل بدنه» در مستنداتِ همین فایل کمی سخاوتمندانه است.)
**پیشنهاد:** افزودنِ `RawQuery` به پیامِ امضا (با تستِ بازگشت) یا مستندسازیِ صریحِ «پارامترها امضا نمی‌شوند». پنجرهٔ replay ۶۰ ثانیه‌ای هم در خودِ کد پذیرفته و مستند شده — تا امروز چون همهٔ اندپوینت‌ها خواندنی‌اند بی‌خطر است، اما اگر روزی یک اندپوینتِ تغییردهنده اضافه شود، باید nonce اضافه شود.

## ۵. نکات ریزِ دیگر (بدون اثر امنیتی)

- `hami` در حالت بی‌آرگومان، `-xray-config` و `-reload-cmd` را در خطِ راهنمای `web serve` نشان نمی‌دهد، در حالی که `hami web serve` خودش چاپ می‌کند (`cmd/hami/main.go` / `cmd/hami/web.go`). همچنین `hami inbound` در فهرستِ راهنما نیست.
- صفحهٔ وضعیتِ مشتری فقط فارسی و بدون انتخابِ زبان است (بقیهٔ محصول دوزبانه است) — برای مشتریانِ غیرفارسی‌زبان قابلِ بهبود.
- هدرهای امنیتی (`X-Frame-Options: SAMEORIGIN`، `frame-ancestors 'self'`، CSP سخت‌گیرانه بدون CDN) درست و متناسب انتخاب شده‌اند — فقط توجه داشته باشید که همین هدرها عمداً جلوی embed شدنِ پنل در جای دیگر را می‌گیرند.
- تست‌های `-race` همه سبز است، ولی توجه: `web serve` و جمع‌کنندهٔ ترافیک **دو فرایند جدا** هستند، پس هیچ‌کدام از قفل‌های درون‌حافظه‌ای مسئلهٔ F4 را پوشش نمی‌دهند؛ راه‌حل باید در سطح SQL باشد.

اولویتِ رفع، به ترتیبِ اثر بر کسب‌وکار: **F1 → F2 → F3 → F4** (سه مورد اول با هم، کمتر از یک روز کار، هم‌راستا با همان شش ستونی که README وعده داده است).

می‌توانم همین حالا:
1. تایمرهای `hami-traffic` و `hami-notice` را به `scripts/install.sh` اضافه کنم (F1)؛
2. فیلترِ انقضا/سهمیه را در `EndpointsFromStore` بگذارم + تستِ بازگشتی (F2)؛
3. `clientKey` را با پرچمِ `-trusted-proxies` امن کنم (F3)؛
4. شکافِ «Scorpion» را تمیز کنم (F6).

فقط بگویید کدام‌ها را پیاده کنم — همه روی همین شاخه (`arena/01a104ef-hami-panel`) و با تست.

## ۷. چه چیزی رفع شد و چطور آزموده شد

همهٔ تغییرها روی شاخهٔ `arena/01a104ef-hami-panel`، با تست، و بدون هیچ تغییرِ ناسازگارکننده در داده یا رابط کاربری.

| یافته | کار انجام‌شده | آزمون |
|---|---|---|
| **F1** | نصاب دو تایمر می‌سازد و فعال می‌کند: `hami-traffic.timer` (هر دقیقه) و `hami-notice.timer` (روزانه، با `HAMI_TELEGRAM` به تلگرام). `HAMI_TRAFFIC_TIMER=no` / `HAMI_NOTICE_TIMER=no` برای کسی که خودش زمان‌بندی می‌کند | کل نصاب در سندباکس با `systemctl` تقلبی اجرا شد؛ یونیت‌ها، فعال‌سازی تایمرها و صفحهٔ ورودِ زنده بررسی شد |
| **F2** | قاعدهٔ واحد `store.Client.ActiveNow` ساخته شد و `xray.EndpointsFromStore` کاربرِ منقضی/تمام‌شده را از کانفیگِ هسته حذف می‌کند (رکورد و مصرف در پایگاه‌داده می‌ماند، تمدید دوباره فعالش می‌کند) | `TestExpiredClientIsNotInTheConfig`، `TestClientOverQuotaIsNotInTheConfig`، `TestActiveAndUnlimitedClientsStayInTheConfig` + آزمونِ سرتاسری: لینکِ ذخیره‌شده از کانفیگ بیرون رفت |
| **F3** | `-trusted-proxies` اضافه شد؛ پیش‌فرض «هیچ‌کس را باور نکن» و نصاب `127.0.0.1/8` را می‌دهد. آخرین گامِ `X-Forwarded-For` ملاک است و مقدار نامعتبر نادیده گرفته می‌شود | `auth_test.go`: بی‌پروکسی، با پروکسی، چند هدر، هدر خراب، تحلیل CIDR |
| **F4** | `store.AddUsage` فقط `up_bytes/down_bytes/last_seen` را می‌نویسد؛ تصمیمِ خاموش‌کردن بعد از **بازخوانی** ردیف گرفته می‌شود | `TestCollectionDoesNotUndoAConcurrentEdit`، `TestCollectionNeverReEnablesADisabledClient` |
| **F2+F1 در عمل** | جمع‌کننده خودش کانفیگ را بازمی‌سازد (`-config`) و بعد هسته را تازه می‌کند (`-reload-cmd`) — ری‌استارت با کانفیگِ کهنه، کاربرِ خاموش‌شده را برنمی‌گرداند. ری‌استارت فقط در دقیقه‌هایی که کسی خاموش شد اجرا می‌شود | آزمونِ سرتاسری با Xray تقلبی: کانفیگ بازنویسی شد، کاربر از فایل بیرون رفت، و در دورِ دوم که تغییری نبود **هیچ ری‌استارتی رخ نداد** |
| **F6** | «Scorpion» از صفحهٔ وضعیت (الان از `link.DefaultBrand`)، راهنمای بارکد و نامِ اکانتِ بات (`hami-…`) برداشته شد | بیلد و تست‌ها؛ جست‌وجوی مخزن دیگر متنِ کاربر-دیده‌ای پیدا نمی‌کند |
| **F7** | `Vary: User-Agent` به پاسخ ساب‌لینک اضافه شد تا کشِ مشترک، بدنهٔ یک اپ را به اپِ دیگر ندهد | `TestServerSubTellsCachesItVariesByAgent` |
| **F5** | query string عمداً امضا نمی‌شود و در بالای `internal/agent/auth.go` به‌صراحت نوشته شد تا پارامترِ تغییردهنده کنارِ این امضا اضافه نشود | — |

**وضعیت نهاییِ مخزن پس از تغییرها:** `gofmt -l` خالی، `go vet ./...` پاک، `go test ./...` و `go test -race ./...` روی هر ۱۷ بستهٔ تست سبز.

### عارضهٔ جانبیِ آگاهانه (F3)

پیش‌فرضِ امن («هیچ هدری باور نمی‌شود») اگر پنل پشتِ reverse proxy باشد، یعنی همهٔ بازدیدکنندگان یک کلید می‌گیرند و پنج گذرواژهٔ اشتباه از هرکسی می‌تواند موقتاً همه را قفل کند. به همین دلیل نصاب به‌طور پیش‌فرض `127.0.0.1/8` را می‌دهد (پنل روی loopback است و پروکسی روی همان ماشین) و خلاصهٔ نصب هم صریح می‌گوید اگر پروکسی‌ای در کار نیست `HAMI_TRUSTED_PROXIES=none` بگذارید.

### چیزهایی که عمداً دست نزدم

- **`Cache-Control: no-store` شرطی** — خودتان نوشته‌اید که پاسخِ خالی نباید ساعت‌ها کش شود؛ رفتار را تغییر ندادم و فقط `Vary` را اضافه کردم.
- **اجرای پنل و هسته با کاربر root** — سخت‌سازیِ درست این است که هر سرویس کاربر خودش را داشته باشد (`User=hami` + `chown` روی پایگاه‌داده و پوشهٔ کانفیگ). چون در سندباکس امکان آزمودنِ مالکیت فایل‌ها نبود، انجامش ندادم؛ پیشنهاد می‌شود جدا و با آزمونِ واقعی روی سرور انجام شود.
- **صفحهٔ وضعیتِ مشتری** هنوز فقط فارسی است (بقیهٔ محصول دوزبانه است).
