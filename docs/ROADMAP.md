# نقشهٔ راهِ پنل حامی (Hami Panel)

منطقِ ترتیب: **اول چیزی که جلوی خرابی را می‌گیرد، بعد چیزی که امکانات اضافه می‌کند.**
هر مرحله باید به‌تنهایی قابلِ استفاده و قابلِ انتشار باشد.

## مرحلهٔ ۰ — پایه (اکنون اینجا هستیم)
- [x] مخزن، مجوزِ GPL-3.0، مستندات
- [x] `internal/link`: تولیدِ لینک برای vless / vmess / trojan / shadowsocks
- [x] تستِ بازگشت برای «نشتِ تنظیمات Reality از اینباندِ دیگر»
- [x] اعتبارسنجیِ اینباندِ نیمه‌پیکربندی‌شده (خرابی باید اینجا فریاد بزند)
- [x] مدلِ داده (اینباند، کلاینت، ترافیک، گره، لاگِ رویداد) + مهاجرت‌ها
- [x] مدیریتِ فرایندِ Xray و تولیدِ کانفیگِ سازگار با لینک‌ها (`internal/xray`, دستورِ `hami gen`)
- [x] آزمونِ زندهٔ همان لحظه — در مرحلهٔ ۱ با `hami canary` انجام شد

**خروجی تا اینجا:** `hami gen` از یک مشخصات، کانفیگِ Xray و لینکِ همان اینباند را
می‌سازد. کلیدِ خصوصی واردِ لینک نمی‌شود و تنظیماتِ اینباندِ دیگر نشت نمی‌کند.
`hami canary` با خودِ همان لینک وصل می‌شود و عبورِ ترافیک را تأیید می‌کند.

## مرحلهٔ ۱ — پایداری (اولویتِ اولِ کاربر)
- [x] **کانِری‌تست:** پنل با خودِ لینک وصل می‌شود و رد شدنِ ترافیک را تأیید می‌کند (`hami canary`؛ VLESS و VLESS+Reality روی 127.0.0.1 با Xray 26.3.27)
- [x] نگهبانِ داخلی: بررسیِ پورت، TLS، صحتِ لینک؛ هشدار؛ اگر پورت بسته باشد یک‌بار از روی همان مشخصات ری‌استارت می‌شود و تنظیماتِ اینباندِ دیگر را کپی نمی‌کند (`hami guard`)
- [x] پین‌کردنِ نسخهٔ هسته + ارتقای مرحله‌ای با بازگشت خودکار (`hami pin` / `hami upgrade`؛ اگر آزمونِ نسخه شکست بخورد باینری قبلی برمی‌گردد. نسخهٔ آزمون‌شده: 26.3.27)
- [x] بک‌آپ/بازیابیِ یک‌دستوری (پایگاه داده + تنظیمات) (`hami backup` / `hami restore`؛ tar.gz شامل panel.db + PIN)
- [x] گزارشِ رویدادها (audit log)؛ `hami audit -db panel.db` و ثبتِ رویداد از guard / canary / backup / restore / upgrade

## مرحلهٔ ۲ — کاربران و اشتراک
- [x] کاربر، سهمیه، انقضا: `hami user create/list/show/set/enable/disable/delete` — سهمیهٔ گیگابایتی، انقضای روزانه/RFC3339، توکنِ اشتراک برای هر کاربر
- [x] بازنشانیِ دوره‌ای: `hami user reset` (سوابقِ ترافیک در جدولِ traffic می‌ماند) — برای کرونِ دوره‌ای
- [x] ساب‌لینکِ چندقالبه: `hami sub serve` با قالب‌های v2ray / Clash(Mihomo) / sing-box / Shadowrocket — انتخاب با ?format= یا User-Agent؛ هدر Subscription-Userinfo
- [ ] ~~محدودیتِ تعداد دستگاه (IP limit)~~ فیلد+CLI آماده است (`-ip-limit`)؛ اعمالِ واقعی نیازمندِ گره/عاملِ مرحلهٔ ۳ است
- [ ] ~~محدودیتِ سرعت~~ فیلد+CLI آماده است (`-speed`)؛ اعمالِ واقعی نیازمندِ گره/عامل است
- [x] هشدار به کاربر: `hami notice` (کرون) — نزدیکِ انقضا/سقف و تمام‌شده‌ها را چاپ، در audit ثبت و به تلگرام (آمادهٔ -telegram) می‌فرستد
- [x] صفحهٔ وضعیتِ مشتری + QR: `/sub/{token}/status` — QR داخلی بدون وابستگیِ خارجی (رفت‌وبرگشتی با دیکدر آزموده شد)

## مرحلهٔ ۳ — چندسروره و فِیل‌اُور
- [x] عاملِ سبک روی هر گره + ارتباطِ امضا‌شده با پنلِ مرکزی — `hami agent run`، پروتکلِ امضای HMAC با امضای کل بدنه و پنجرهٔ زمانی ۶۰ ثانیه (`hami node add/list/check/remove`)
- [x] سلامتِ هر گره و حذفِ خودکار از ساب‌لینک — `node check` وضعیت را در پایگاه‌داده می‌نویسد و ساب‌لینک گره‌های down را حذف می‌کند (unknown/unstable همچنان سرو می‌شوند تا نگرانیِ «چک نکردم» به قطعیِ مشتری تبدیل نشود)
- [x] ساب‌لینکِ هوشمند: فقط گره‌های سالم — گیتِ سلامت در `subs.Entries`؛ ترتیب‌دهیِ کیفیتی معنا پیدا می‌کند موقعِ چنداینباندِ هم‌زمان به‌ازای هر کاربر (در مسیرِ مرحلهٔ ۵)
- [x] توزیعِ کاربر روی چند گره — `user create -node auto` کم‌بارترین اینباندِ روی گره‌های سالم/نامشخص را انتخاب می‌کند (گره‌ی down همیشه کنار گذاشته می‌شود؛ برابری → کمترین شناسه، قطعی) و `user create -node NAME` توزیعِ دستی

## مرحلهٔ ۴ — پروتکل‌های نو و ضدِ فیلترینگ
- [x] sing-box به‌عنوان هستهٔ دوم (Hysteria2، TUIC، AnyTLS) — `internal/singbox` با Build/Links، `hami gen -core singbox`، لینک‌های `hysteria2://` / `tuic://` / `anytls://`، ساب‌لینک چندقالبه (v2ray/Clash/sing-box) برای هر سه
- [x] قالب‌های آماده برای VLESS+Reality، XHTTP، HTTPUpgrade، gRPC + sing-box (`hami template list` / `apply` — ۱۱ قالب: ۷ تا VLESS + ۴ تا sing-box: hysteria2-tls/tuic-tls/anytls-tls/anytls-reality)
- [x] بررسیِ خودکارِ سلامتِ مقصدِ Reality (dest/SNI) و اثرانگشتِ uTLS (`hami reality check -dest HOST:PORT -sni SNI` — TLS handshake + VerifyHostname، تست با cert خودامضا)
- [x] چرخشِ ShortID و کلید (`hami reality rotate -db panel.db -id ID [-new-sid] [-new-key]` + `hami reality keygen` — X25519 با ecdh، ShortID هگز تصادفی)
- [x] اینباندِ خصوصی/اختصاصی (ادمین-فقط) — `is_private`، `hami inbound add --private`، حذف از `LeastLoadedInbound` و توزیع auto، لیست با ستون PRIVATE، فقط کلاینت‌های متصل به آن اینباند لینک می‌گیرند (جایگزین امن برای دستکاری ساب‌لینک)

## مرحلهٔ ۴.۵ — پنل وب HP-UI (انجام شد)
- [x] صفحهٔ ورود اختصاصی HP-UI / HAMI PANEL — طراحی کاملاً متفاوت از 3X-UI، Split layout (برندینگ چپ، فرم راست)، تم‌های روشن #9DC183 / تیره #0B6623 / خیلی تیره #043927، لوگو H، بدون Hello/Welcome
- [x] سرور وب `hami web serve -db panel.db -addr :8080` — مسیرهای /hp-ui/login و /sub/{token} و /sub/{token}/status
- [x] احراز هویت ادمین — گذرواژه با پی‌بی‌کی‌دی‌اف‌۲ و نمکِ جداگانه برای هر حساب، نشست در پایگاه‌داده، کوکی فقط‌اچ‌تی‌تی‌پی، کندکردنِ پس از پنج تلاشِ ناموفق، ثبتِ ورودِ ناموفق در گزارش رویدادها، ابطالِ همهٔ نشست‌ها هنگام تغییرِ گذرواژه (`hami admin create/list/passwd/delete`)
- [x] داشبورد اینباند/کاربر/نود/لاگ — پنج زبانه، دوزبانه فارسی و انگلیسی با چینشِ راست‌چین، همان سه تمِ صفحهٔ ورود، جدولِ اینباند و کاربر و گره و رویداد، نمایشِ لینکِ هر کاربر از روی اینباندِ خودش، فعال/غیرفعال کردن و صفرکردنِ مصرف، بدون هیچ فایلِ بیرونی

- [x] ساخت و ویرایشِ اینباند و کاربر از خودِ داشبورد — دکمهٔ «اینباندِ تازه» و «کاربرِ تازه» با پنجرهٔ مودال، ساختِ دسته‌ای تا صد کاربر با پسوندِ شماره، ویرایشِ سهمیه و مهلت و سقفِ دستگاه، تمدید از همین حالا و برگرداندنِ کاربرِ غیرفعال، چرخشِ نشانهٔ اشتراک، حذفِ کاربر و اینباند با هشدار
- [x] مسیرِ مشترکِ ساخت برای خطِ فرمان و وب — `internal/provision` تا منطقِ ساخت در دو جا تکرار نشود
- [x] نمایشِ بارکدِ هر کاربر داخلِ داشبورد — ساختِ لینک و بارکد در همان پروسه، بدون ارسالِ کلید به هیچ سرویسِ بیرونی
- [x] بارکدساز تا نسخهٔ ۹ و انتخابِ خودکارِ ماسک — لینک‌های بلندِ ری‌الیتی تا دویست‌وسی بایت جا می‌شوند و با اسکنرِ واقعی خوانده می‌شوند

- [ ] اتصال به درگاه/کیف پول و تمدیدِ خودکار

## مرحلهٔ ۶ — مهاجرت و پذیرشِ عمومی
- [x] واردات از پنل‌های دیگر — بخشی از خودِ پنل است نه ابزار جدا: `hami import scan|plan|apply`
  - خانوادهٔ ایکس‌یوآی: ثنائی نسخهٔ تازه با جدول کلاینت جداگانه، ثنائی و علیرضا با کلاینت داخل تنظیمات، و نسخهٔ قدیمی بدون جدول ترافیک
  - مرزبان: کاربران و پروکسی‌ها و میزبان‌ها؛ چون تعریف اینباند در فایل پیکربندی ایکس‌ری است نه پایگاه داده، با سوییچ `-xray-config` کامل می‌شود
  - پنل مبدأ اصلاً باز نمی‌شود برای نوشتن: اول کپی می‌شود، کپی فقط‌خواندنی باز می‌شود، و چک‌سام فایل اصلی قبل و بعد مقایسه می‌شود
  - `plan` هیچ چیزی نمی‌نویسد؛ `apply` بدون `-yes` اجرا نمی‌شود، قبل از نوشتن از پایگاه دادهٔ مقصد نسخهٔ پشتیبان می‌گیرد، و بعد از نوشتن همه چیز را دوباره می‌خواند و با مبدأ مقایسه می‌کند
  - دوباره اجرا کردنش چیزی را دوباره وارد نمی‌کند؛ تداخل پورت یا نام تکراری خطا می‌دهد نه بازنویسی
  - حفظ می‌شود: شناسه، نشانهٔ اشتراک (لینک‌های داخل اپ مشتری کار می‌کنند)، سهمیه، مصرف، انقضا، سقف دستگاه، فعال یا غیرفعال بودن، و تاریخ عضویت
- [x] کوچ از داشبورد — زبانهٔ «کوچ» با سه گام: فایل پنل قبلی را بفرست یا نشانی‌اش روی همین سرور را بده، ببین داخلش چیست، بعد بیاور
  - همان بستهٔ واردات پشت دکمه است، پس خط فرمان و داشبورد دقیقاً یک رفتار دارند
  - گام دوم چیزی نمی‌نویسد؛ جدول ورودی‌ها و هشدارها و موارد نیامده و تداخل‌ها را نشان می‌دهد
  - گام سوم دوباره از مبدأ می‌خواند و اگر تعداد عوض شده باشد اجرا نمی‌شود، تا چیزی که تأیید کرده‌اید همان باشد که نوشته می‌شود
- [ ] خروجیِ استاندارد برای ابزارهای رایج
- [ ] مستنداتِ کامل به انگلیسی و فارسی
- [x] اجرا روی سرور واقعی — سرویس systemd روی فنلاند، اچ‌تی‌تی‌پی‌اس با گواهی لِتس‌اینکریپت، پورت ۲۰۵۴، دسترسی فقط از محدوده‌های همراه اول با همان ipset پنل قبلی، و قلاب تمدید گواهی تا بعد از هر تمدید سرویس دوباره بخواند
- [x] لینک اشتراک عمومی — سرویس جدا روی حلقهٔ محلی، از راه تونل کلودفلر روی `sub.example.com/sub/`؛ با همهٔ اپراتورها کار می‌کند در حالی که خود پنل فقط از محدوده‌های همراه اول باز است
- [ ] بستهٔ نصب (deb / rpm / docker) و اسکریپتِ یک‌خطی
